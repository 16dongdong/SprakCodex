# 直连观测

直连观测是 CodexManager 内置的本地网络观测引擎，不启动 `CProxy.exe`，也不创建第二个管理进程。

## 使用方式

1. 打开“Codex 接入方式”页面。
2. 在“直连观测”卡片点击“启用观测”。
3. Windows 后台扫描器自动发现已运行及后续启动的 Codex 进程，不要求通过“项目启动”打开终端。
4. 使用结束后可关闭观测；关闭观测不会退出用户的 Codex 进程。

启用设置保存在数据库，后端启动时按设置恢复运行资源。Windows 签名密钥使用当前用户范围的 DPAPI 保护，公开证书保存在运行目录；不会安装系统根证书、修改 `auth.json`、官方 provider/base_url 或系统代理。Windows 项目启动不把当次观测端口写入终端代理环境。站点证书有效期 7 天，后台每小时检查，并在到期前一天整批续签。

退出应用不等于关闭观测：已接入且匹配构建的客户端会把完成元数据写入数据目录的 `observationCompletions`，宿主恢复后入库并清理已确认文件。主动点击“关闭观测”才撤销该选择。无持久化会话、正常宿主退出和强制结束后的补录均已通过真实 CLI 验证；尚未接入的客户端在宿主离线期间不会被自动加载模块。

## 记录和费用

- `/v1/responses`、`/v1/chat/completions`、Codex Responses 路径支持非流式、SSE 和 WebSocket。
- 网络来源保存方法、路径、状态、耗时、模型、实际用量和错误原因；认证头、Cookie、提示词、工具参数、响应正文不会写入数据库。
- 已建立连接通过原生完成入口或客户端持久化事件补充实际用量，显示为“客户端事件”。这类来源不填充未观察到的 HTTP 状态、URL、方法或时长；模型标明来自客户端上下文。原生入口按 PDB 身份及指令字节匹配，目前已验证 Windows x64 Codex CLI `0.153.4`；不匹配的构建不猜测偏移。
- 原生事件只包含响应/会话/轮次标识、provider、模型上下文、时间及用量。临时文件写完并同步后原子发布，数据库确认前不删除，重放按响应 ID 去重。
- 同一响应 ID 的网络来源和客户端事件合并为一条请求，避免重复统计及重复费用快照。
- 有完整服务端用量和匹配价格时，直连观测会创建现有 `request_charge_snapshots` 费用快照，并更新该请求的费用字段。
- 费用快照不关联钱包、API 密钥或平台额度，不会产生扣费账本。
- 服务端未返回完整 usage 或价格缺失时，费用保持未知并写明原因，不生成零价快照。

## 网络边界

观测只解密 `chatgpt.com` 和 `api.openai.com` 的 443 连接。原生接入携带客户端已经选择的原 IP 或本机明文 HTTP 代理端点，宿主保留该出口，不再把宿主代理设置替代客户端路径。显式连接观测代理端口而没有原生路由头的客户端，才使用宿主出口配置。未观察的原生协议沿原 IP/端口透传。

Codex 保持官方请求地址；本地回环监听是传输观测入口，不是账号池网关，也不意味着将官方 provider 指向本地地址。进程发现、原生加载就绪和请求实际被观察到是三个不同验收结果，不能相互替代。当前覆盖与未完成项见 [直连观测验收记录](report/directObservationAcceptance.md)。

## 安装资源

Windows 安装资源为 `observationHook8.dll`，使用第八版就绪协议及独立的 `relay8.json` 网络控制文件；构建产物来源为 `backend/target/observationBuild/release/cphook.dll`。新版不会通过重新激活旧网络配置升级已加载的模块，也不主动卸载旧回调。正式安装与实际界面验证应使用同一次桌面构建生成的 EXE 和 DLL。
