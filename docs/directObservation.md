# 本机接入

本机接入是 SprakCodex 内置的本地连接与记录引擎，不启动 `CProxy.exe`，也不创建第二个管理进程。

## 使用方式

1. 打开“账号”页面。
2. 打开“本机接入”开关。
3. Windows 后台扫描器自动发现已运行及后续启动的 Codex 进程。
4. 使用结束后可关闭观测；关闭观测不会退出用户的 Codex 进程。

启用设置保存在数据库，后端启动时按设置恢复运行资源。Windows 签名密钥使用当前用户范围的 DPAPI 保护，公开证书保存在运行目录；不会安装系统根证书、修改 `auth.json`、官方 provider/base_url 或系统代理。Windows 项目启动不把当次观测端口写入终端代理环境。站点证书有效期 7 天，后台每小时检查，并在到期前一天整批续签。

退出应用不等于关闭观测：已接入且匹配构建的客户端会把完成元数据写入数据目录的 `observationCompletions`，宿主恢复后入库并清理已确认文件。主动点击“关闭观测”才撤销该选择。无持久化会话、正常宿主退出和强制结束后的补录均已通过真实 CLI 验证；尚未接入的客户端在宿主离线期间不会被自动加载模块。

## 记录和费用

- `/v1/responses`、`/v1/chat/completions`、Codex Responses 路径支持非流式、SSE 和 WebSocket。
- 网络来源保存方法、路径、账号标识、认证不可逆指纹、状态、耗时/首响、模型/推理/等级、实际用量和脱敏错误。日志行的“详情”按钮按需读取请求头、JSON 正文和响应事件；认证头、Cookie、令牌字段被掩码。完整请求/响应正文通过自动删除的临时文件顺序采集，入库前统一脱敏，不再限制为固定长度预览；HTTP SSE 保存完整解码报文，WebSocket 保存全部关联帧及握手响应头，重复头值保留。历史和纯客户端完成事件没有网络正文。详情与日志删除级联，非管理员仅能读取自己密钥所属记录。
- 已建立连接通过原生完成入口或客户端持久化事件补充实际用量，显示为“客户端事件”。这类来源不填充未观察到的 HTTP 状态、URL、方法或时长；模型标明来自客户端上下文。原生入口按 PDB 身份及指令字节匹配，目前已验证 Windows x64 Codex CLI `0.153.4`；不匹配的构建不猜测偏移。
- 原生事件只包含响应/会话/轮次标识、provider、模型上下文、时间及用量。临时文件写完并同步后原子发布，数据库确认前不删除，重放按响应 ID 去重。
- 同一响应 ID 的网络来源和客户端事件合并为一条请求，避免重复统计及重复费用快照。
- 有完整服务端用量和匹配价格时，直连观测会创建现有 `request_charge_snapshots` 费用快照，并更新该请求的费用字段。
- 费用快照不关联钱包、API 密钥或平台额度，不会产生扣费账本。
- 服务端未返回完整 usage 或价格缺失时，费用保持未知并写明原因，不生成零价快照。

## 网络边界

观测只解密 `chatgpt.com` 和 `api.openai.com` 的 443 连接。原生接入携带客户端已经选择的原 IP 或本机明文 HTTP 代理端点，宿主保留该出口，不再把宿主代理设置替代客户端路径。显式连接共享代理端口而没有原生路由头的客户端，才使用宿主出口配置。未观察的原生协议沿原 IP/端口透传。

观测与代理中转共用公开端口：回环连接的 `CPROXYH1` 原生头和 HTTP CONNECT 在 TCP 入口分流，普通 HTTP 原样交给既有网关路由；远端连接不进入本机观测分流。独立观测监听仅用于隔离测试。

Codex 保持官方请求地址；本地回环监听是传输观测入口，不是账号池网关，也不意味着将官方 provider 指向本地地址。进程发现、原生加载就绪和请求实际被观察到是三个不同验收结果，不能相互替代。当前覆盖与未完成项见 [直连观测验收记录](report/directObservationAcceptance.md)。

## 内存部署

Windows 构建会先编译观测载荷，再由 `codexmanager-service` 的构建脚本通过 `include_bytes!` 链接进宿主 EXE。运行期从内嵌 PE 字节完成重定位、导入解析、异常表注册、区段权限收紧和初始化，不向安装目录释放 DLL 或网络控制文件。Relay 配置通过版本化命名页映射发布；宿主退出后映射对象随句柄释放，进程内模块不会沿用旧端口。

安装包只携带主程序和独立更新器。新版首次启动会清理旧安装遗留的 `observationHook9.dll`；已经映射旧模块的客户端保持原生命周期，新进程使用第十二版内存部署协议。

`updateAgent.exe` 在主程序启动时复制到按 PID 隔离的临时路径并作为看门狗运行。主程序通过私有 stdin 管道同步每个目标的 PID、创建时间、映像基址、卸载入口和异常表；主程序正常退出、异常退出或进入更新流程后，看门狗会先恢复全部回调入口、排空正在执行的回调、注销异常函数表并释放目标进程中的映像。更新完成或普通启动时，新主程序必须先完成看门狗握手，再按持久化开关重新部署观测映像。

## 会话导入与续期

账号导入可整段粘贴 `/api/auth/session` JSON，识别 `accessToken`、用户信息以及存在时的刷新字段；不保存整个会话响应。重复导入同一主体时，缺少刷新字段保留已存授权，不以空值撤销它。只有 Access Token 的响应不等于刷新授权；过期后通过导入界面的“登录授权”完成浏览器授权，或重新导入新会话。已有有效 Refresh Token 的账号继续走现有自动刷新与轮换流程。

### 现有连接恢复与身份展示

第十二版模块在宿主启用或恢复时，通过 Windows 本进程句柄快照识别仍连已知本机 HTTP 代理的旧 TCP 连接，再借助 Winsock 克隆连接执行定向 shutdown，让客户端自行建立经过共享入口的新连接。原进程和原句柄不被终止，IPC、已接入观测的连接以及未知代理不受影响。此路径在客户端自身执行，不要求每次借助管理员工具处理旧连接。

账号名称仅从本次请求 JWT 的邮箱／名称声明提取作为显示快照，不用于授权；原令牌只保存不可逆指纹。相同账号和相同指纹的历史网络记录可补齐名称，纯客户端事件不猜测身份。详情通过列表提供的 `traceId` 查询，四个区域分别显示请求头、请求体、响应头、响应体；不把不透明 trace 强转为数值行号。
